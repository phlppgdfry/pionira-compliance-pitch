01 — Wat ik las, en wat opviel

Dit is geen incident. Het is een patroon.

Drie landen, drie regelgevers, drie keer een eigen dossier. Frankrijk, Duitsland en Nederland zullen niet de laatste blijven — de EU-richting is duidelijk digitaal en verplicht.

02 — Het voorstel

Een Compliance Connector Framework

Niet nóg een feature, maar een manier om nieuwe wetgeving een configuratietaak te maken in plaats van een implementatietraject.

Het idee is eenvoudig genoeg om aan iedereen uit te leggen: op het moment dat een chauffeur of transporteur een document tekent, wordt dat één keer centraal gemeld — als een bericht op een soort interne "postbus" (Azure Service Bus). Elk land dat een melding verwacht — Vlaanderen, de EU, Spanje, en morgen misschien Frankrijk — heeft zijn eigen "loket" dat dat bericht oppikt en zelf afhandelt volgens de regels van dat land. Het documentproces zelf verandert niet; alleen de manier waarop nieuwe landen worden aangesloten.

Eén gebeurtenis, meerdere onafhankelijke "loketten" — elk land een eigen connector, elk met eigen foutafhandeling.

Waarom dit nu telt

Op 21 mei 2026 ging DIWASS EU-breed live — tientallen landen die tegelijk beginnen registreren bij één centraal systeem. Zulke lanceringen zijn zelden storingsvrij op dag één. Een connector met eigen retry- en foutafhandeling zorgt ervoor dat een instabiele overheids-API nooit een transport tegenhoudt — het document blijft gewoon geldig, de melding volgt automatisch zodra het systeem weer bereikbaar is.

03 — Voor de engineers in het team

Hoe dit er in code uitziet

Een eenvoudige interface volstaat om elk land als losstaand, testbaar onderdeel te bouwen — zonder de rest van het systeem te raken:

ComplianceConnectors / IComplianceReporter.cs
public interface IComplianceReporter
{
    // elk land implementeert dit contract eenmalig
    string RegimeCode { get; } // "BE-MATIS" · "EU-DIWASS" · "ES-DECA"
    bool AppliesTo(SignedDocument doc);
    Task ReportAsync(SignedDocument doc, CancellationToken ct);
}

// registratie: nieuw land = nieuwe regel, geen nieuw project
public class DiwassReporter : IComplianceReporter { /* ... */ }
public class DecaReporter    : IComplianceReporter { /* ... */ }
public class MatisReporter   : IComplianceReporter { /* ... */ }

// Service Bus subscriber: elke connector krijgt eigen queue,
// eigen retry-policy en dead-letter — één trage overheids-API
// kan nooit de andere landen of het documentproces blokkeren.
services.AddServiceBusProcessor("document.signed", opts =>
{
    opts.MaxDeliveryCount = 8;
    opts.MaxAutoLockRenewalDuration = TimeSpan.FromMinutes(10);
});

Concreet raakt dit precies de vaardigheden uit de vacature: C# / ASP.NET voor de connector-services, Azure Service Bus als ontkoppelde berichtenlaag, Azure SQL voor de audittrail per melding, en de vermelde .NET Framework → .NET Core-migratie is het natuurlijke moment om dit uit de bestaande monoliet te lichten.

04 — Een extra observatie

eWastra staat op de Azure Marketplace

eWastra is te vinden als "transactable SaaS"-vermelding op de Microsoft Azure Marketplace. Dat betekent dat er ergens al gewerkt wordt met Microsofts SaaS Fulfillment API en metered billing — voor het automatisch aanmaken van klantaccounts en het afhandelen van facturatie via Azure AD-tenants. Dat is een vrij specifieke, weinig voorkomende Azure-vaardigheid, en precies het soort "gedistribueerde systemen integreren" waar de vacature naar vraagt. Een klein maar concreet signaal dat ik verder keek dan de functietitel alleen.

05 — Hoe dit zou landen, stap voor stap

Geen big bang. Eén land als bewijs, dan de rest.

FASE 0

Inventariseren wat er al is

De bestaande MATIS-export en eventuele DIWASS-koppeling in kaart brengen — dit voorstel gaat uit van wat op de eigen website beschreven staat; het echte startpunt bepaalt het team zelf.

FASE 1

Eén land als pilot herbouwen

De bestaande MATIS-logica achter het IComplianceReporter-contract plaatsen, zonder gedragswijziging — het bewijs dat de ontkoppeling werkt, met minimaal risico.

FASE 2

DeCA (Spanje) als eerste échte test

Verplicht vanaf oktober 2026 — dus op korte termijn. De tweede connector bouwen bevestigt of weerlegt de aanname binnen enkele weken, ruim op tijd.

FASE 3

Zelfbedieningsonboarding

Het volgende land — of de volgende ERP/TMS-partner uit de lijst van 40+ — aansluiten wordt een configuratietaak, niet langer een apart project.
